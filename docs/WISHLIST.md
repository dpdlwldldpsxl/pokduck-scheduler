# WISHLIST — 욕심 배출구

> 만들고 싶은데 지금은 안 되는 아이디어를 **여기에만** 적어둠.
> 쓰면 욕심이 풀린다. MVP 검증 후 꺼내서 재평가.
>
> 원칙: `docs/CORE_VALUE.md` 원칙 5 참조.

---

## 등록 양식

```
### [아이디어 제목]
- **누가 요청:** (본인/유저/벤치마킹)
- **등록일:** YYYY-MM-DD
- **왜 지금 안 되나:** (원칙 X 위반 / MVP 외 / 기술 부담)
- **나중에 꺼낼 조건:** (언제 재평가할지)
- **메모:** (자유)
```

## 등록된 아이디어

### 날씨 연동 자동 앰비언트
- **누가 요청:** 본인
- **등록일:** 2026-04-23
- **왜 지금 안 되나:**
  - 날씨 API 키 + 위치 권한 필요 → 온보딩 마찰 증가
  - 원칙 4(전문 앱 테스트) 통과하지만 "귀여움 지수만 높고 핵심 가치 약함"
  - MVP에 필수 아님
- **나중에 꺼낼 조건:** Phase F 이후 (베타 테스터 피드백에 "비 오는 날 감성" 요청 2명 이상)
- **메모:** 위치 권한 거부 유저 fallback 로직 필수. "오늘 서울 비 - 비소리 자동 재생할까?" 알림 형태가 최소 마찰.

## 사용 규칙

1. "지금 만들고 싶다"는 생각 들면 → **코드 먼저 아님. 여기 먼저 기록.**
2. 기록 후 최소 1주일은 묵혀둠. 묵혀도 살아있는 아이디어만 재평가.
3. Phase 완료 시점마다 여기 훑어보고, 통과된 것만 다음 Phase 후보로 이관.
4. 1개월 지나도 안 꺼냈으면 정말 필요했는지 재판단. 아니면 삭제.
